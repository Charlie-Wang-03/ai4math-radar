## Serious chronology conflicts discovered

1. **Wormald**: public GitHub release **2026-10-14 09:27:13Z** precedes the Oct22 Hexagon paper. Its canonical `2026-10-22-` ID currently frames an Oct22 research event. Determine whether to represent an October 14 **initial public proof** and an October 22 **Hexagon preprint deposit** as one record (with stable ID and a distinct event-date field), or as different properly attributed milestones; do not make two duplicate research breakthroughs. The GitHub release is directly claim-matched and should not be dismissed as “repository merely existed”.
2. **Angular Hecke 15/16**: public exact-result GitHub release **2026-10-19 02:08:55Z** precedes Oct22 Hexagon v1. Same policy question; the theorem and its Lean proof were already publicly released.
3. **Ralf Stephan**: original theorem on arXiv in **July**, with Oct18 v4 and Oct20 Hexagon/Palomar. The original date remains a distinct event from Oct20 formalization / registration. The current headline already mentions Palomar; preserve that scope.
4. **arXiv x3**: v1 histories explicitly give **submission click** instants on Oct20; arXiv has a separate announcement stage. Under the published [availability schedule](https://info.arxiv.org/help/availability.html), a routine Tuesday 20:00 US Eastern public announcement would be **Oct21 UTC**, but do not assert any *individual* paper's first public timestamp from a schedule alone. This may be a UTC first-public date conflict in 3 rows.
5. **Acuna** and **sorting networks**: earlier or incomplete machine evidence warrants a claim-matched identity/date review; no date correction justified yet.
