# Batch 25 — historic arXiv first-announcement days from contemporaneously committed feed snapshots

Checked 2026-10-30. Parent work: [Issue #127](https://github.com/Charlie-Wang-03/ai4math-radar/issues/127), [temporal contract v1](../editorial-temporal-contract-v1.md).

## Source authority, interpretation and limitations

[arXiv's RSS feed specification](https://info.arxiv.org/help/rss_specifications.html) distinguishes `arxiv:announce_type=new` (first release on arXiv) from `cross` (new in another category) and `replace` (later revision). The item-level RSS `pubDate` gives the **official announced calendar date**, not a real time-of-day: `00:00:00 -0400` is a standardized feed-date value and MUST NOT be promoted to an exact public UTC timestamp. The [ordinary arXiv Search API `published`](https://info.arxiv.org/help/api/user-manual.html) instead reflects *submitted/processed*, not announced.

These historical daily feeds have rolled out of the live provider endpoints. Two third-party GitHub repositories preserved contemporaneous copies of the **original feed item text**. We inspected an article-ID/title/announce-type/date match against each frozen archive revision, checked the revision's publicly visible commit date, and link the original first-party feed as `chronology.milestone.evidenceUrl`; the **frozen archive revision provides the replayable item-level historical evidence**. The mirror is not itself the primary publisher and is not a source of mathematical verification. We do not infer an exact clock from a mirror's Git commit time or from its file name.

Small editor contract enhancement: the allowlist now recognizes both official `https://rss.arxiv.org/atom/<category>` and `https://rss.arxiv.org/rss/<category>`, while rejecting mirror-only evidence URLs as the primary `arxiv-announcement` authority and still rejecting ordinary `/abs/` pages.

**Important:** The archive `rss_fetch` filenames are *not* the source time authority (e.g. path `2026-10-20` contains genuine RSS item `pubDate` for **Oct21**). These were inspected as bytes returned by the GitHub connector, not guessed by arXiv submission scheduling. The GitHub commit is evidence of **an archived copy**, not the publication timestamp itself.

## Not promoted

- [2609.36663 GenLimitLib](https://arxiv.org/abs/2609.36663): independent archived [cs.LO feed](https://github.com/ehijano/rss_fetch/blob/e597e5120c034115fda2049d72812f2da7f99f3a/rss_data/cs.LO/2026-09-30_cs.LO.xml) shows Sep30 **cross**, and an undated derived record says `new`. The `cs.LG` RSS historical snapshot files are empty, so item-matched original-primary **new** announcement remains unproven at day precision. Do not substitute a cross-listing.
- [2610.26467 Rózsa](https://arxiv.org/abs/2610.26467): historic source-specific `new` RSS listing not found in the reviewed archives. OAI metadata changes and Oct19 submitted time are not enough.
- 2023 ProofNet / Checkmate / LeanDojo: no contemporaneous arXiv daily RSS snapshots from the 2026 feed archive; ProofNet Feb23 retains contradiction with Feb24 v1 submitted. Do not backdate without distinct publication evidence.
- Source authenticity and mathematical correctness are separate: these dates authenticate only arXiv paper announcements and make no claims of journal review, proof correctness, AI attribution, or Lean statement fidelity.

## Publication and regression

- Add day-only `chronology.milestone` to **seven records**; `eventKind: paper-release`, `evidenceKind: arxiv-announcement`, primary `evidenceUrl` set to the per-article source category RSS. All `publishedAt`, old IDs, other source links, summaries, ranks and discover timestamps unchanged.
- Add official provider RSS URL to the strict parser allowlist, retaining HTTPS, exact host and path-shape restrictions and regressions on host spoofing and ordinary arXiv submission pages.
- Require hosted `check`/`docker`, CodeQL, documentation review, and no unresolved review feedback prior to merge.
- If merged onto an otherwise unchanged 314-item `main`, missing optional source chronology among 96 historical date-only fields goes from **19 → 12**; the **96 legacy dates stay 96**. The need for the separate feed/UI chronology migration under Issue #104 is unaffected.
